## 1. Skill 定位

`math-modeling` 是面向数学建模竞赛和一般建模项目的三阶段工作流。它把任务拆成三个相互独立、又可闭环协作的角色：

1. **建模手**：理解题目、检查数据、拆分子问题、选择模型、定义数学形式和验证方案。
2. **编程手**：用 Python 或 MATLAB 实现模型，真实运行，输出数据表、图表和复现信息。
3. **论文手**：仅基于真实模型与运行结果组织论证，按当届官方模板生成完整 Word 论文。

它既支持“从读题到完整论文”的全流程，也支持只执行某个阶段。单阶段任务不应被强制扩展成完整流程。

适用场景包括：

- CUMCM 全国大学生数学建模竞赛；
- MCM/ICM 美国大学生数学建模竞赛；
- APMCM、MathorCup、认证杯、数维杯等；
- 一般优化、预测、评价、统计、图论、仿真和机器学习建模项目。

生成论文只供用户参考，不能直接视为可提交作品。论文结构、格式、页数、摘要、编号和提交要求必须服从目标竞赛**当届官方规则和官方模板**。

## 2. 最核心的设计思想

### 2.1 证据驱动

Skill 的主线不是“先写论文再补结果”，而是：

```text
题目与附件
  → 明确问题、数据、约束和结论类型
  → 选择可实现、可验证的模型
  → 编写并真实运行代码
  → 生成表格、图和复现清单
  → 建立主张—证据映射
  → 生成并验证 DOCX
```

所有数值结论必须来自实际运行；所有图表必须来自程序真实输出；所有引用必须能追溯至 DOI、出版机构页面或可信原始页面。

### 2.2 三阶段解耦与反馈闭环

三个角色职责严格区分，下游发现问题时回到对应上游修正：

- 编程手发现公式不完整、约束冲突、参数定义矛盾或模型无法实现时，不得擅自“改算法绕过”，而应携带报错、数据证据和最小复现返回建模手。
- 论文手发现结论缺少真实结果、图表、公式或文献支撑时，必须退回编程手或建模手补齐，禁止编造。
- 修正后从受阻阶段继续，不重复已经通过的阶段。

### 2.3 渐进式加载

实际使用时先读当前角色的 `SKILL.md`，再按任务需要读取一份或少量参考资料，禁止一次性加载全部算法库和工具说明。典型路由如下：

| 当前需求 | 应加载内容 |
|---|---|
| 选模型 | 建模手入口、`建模设计理论.md` |
| 查具体算法 | `算法索引.md` + 一个或少数相关 `assets/*.md` |
| Python/MATLAB 实现 | 编程手入口、`工作流程.md` |
| MATLAB 工具箱与规范 | `MATLAB规范.md` |
| 绘图 | `可视化规范.md`，必要时 `常见模式.md` |
| 搜索论文 | `tools/paper_search/SKILL.md` |
| 读取题目 PDF | `tools/pdf/SKILL.md` |
| 处理 Excel | `tools/xlsx/SKILL.md` |
| 生成 Word | 论文手入口、论文格式规范、`tools/docx/SKILL.md` |

## 5. 全局建模约束

### 5.1 先理解，后选模型

必须先完整理解：

- 题目要求；
- 全部附件；
- 子问题目标；
- 输入、输出和评价口径；
- 变量、单位和约束；
- 数据质量、时间范围和空间关系；
- 官方格式与提交要求。

先明确“每个子问题最终要回答哪类结论”，再决定用什么模型。结论目标只描述输出类型和评价标准，不能预写尚未计算出的数值。

### 5.2 每个子问题最多两个独立模型体系

可以是：

- 一个主模型；
- 主模型 + 一个对比或验证模型；
- 两个串联模型，各自完成必要阶段。

不单独计作模型的内容包括：灵敏度分析、残差分析、消融实验、交叉验证、误差检验和可视化。

物理题按“模型族”计数。同一控制机理、核心变量和控制方程在不同近似阶次、反射次数、边界简化或数值精度下的表达，通常属于同一模型族。只有控制机理、状态变量、边界条件体系或求解目标发生实质变化，才另算独立模型。

两个模型得到相近结论不构成删除理由，是否保留取决于研究目的、方法差异和证据价值。

### 5.3 创新要求

禁止把常见简单模型直接套用后改名冒充创新。创新可以来自：

- 对问题结构的专门刻画；
- 有依据的数据预处理和特征构造；
- 更贴近题意的目标或约束；
- 算法改进；
- 串并联模型设计；
- 稳健性、灵敏度、消融或外部对照等验证方式。

复杂度本身不是优点。模型必须适配题目、可实现、可验证、可解释。

### 5.4 数据与阈值

缺失、异常、量纲、阈值和判定标准必须来自题目、当届官方规则、领域文献或数据分析结果。无法确认的事实应列为待确认项，不能补造。

## 6. 建模手：完整职责

### 6.1 唯一固定交付物

1. `PROJECT_ROOT/题目分析报告.md`
2. `PROJECT_ROOT/术语表格.md`

模型合同属于分析报告内部内容，不另建第三个交付文件。

### 6.2 工作顺序

1. 枚举题目、附件、数据表、图片和模板，并记录哈希或版本。
2. 按子问题整理目标、约束、输入、输出和评价口径。
3. 检查字段、单位、缺失、异常、重复、时间顺序和空间关系。
4. 先定义每个子问题要得出的“结论类型”。
5. 评估候选模型，每题最多两个独立模型体系。
6. 明确变量、参数、目标函数、约束、假设、边界条件、算法、停止条件、输入输出、依赖和验证方式。
7. 使用 OpenAlex + AnySearch 搜索理论依据，并到 DOI 或出版页面核验。
8. 写入两个固定文件并按质检清单验收。

### 6.3 模型合同内容

| 项目 | 必须回答的问题 |
|---|---|
| 任务定义 | 每个子问题要计算、预测、评价还是决策什么 |
| 数据 | 字段、单位、范围、质量和只读文件是什么 |
| 结论类型 | 最终需要哪类结论与指标 |
| 模型 | 选一个还是两个模型，为什么适配 |
| 数学定义 | 变量、参数、目标、约束、假设、边界条件 |
| 实现 | 输入输出、算法步骤、停止条件、依赖 |
| 验证 | 用什么数据、误差、稳定性或对照检验 |
| 风险 | 哪些条件不满足时必须回退或换方案 |

### 6.4 `题目分析报告.md` 至少包含

1. 题目与附件清单；
2. 子问题拆解；
3. 数据理解与预处理计划；
4. 假设及依据；
5. 每题模型与数学定义；
6. 算法步骤、输入输出和验证方式；
7. 编程依赖和候选图表；
8. 风险与回退条件；
9. 文献依据。

### 6.5 `术语表格.md` 至少包含

- 中文术语；
- 英文术语；
- 符号；
- 定义；
- 单位；
- 首次出现位置；
- 禁止混用的近义词。

### 6.6 设计原则

- **充分性**：覆盖目标、关键约束和关键数据。
- **可证伪性**：预先定义会让模型失败的检验。
- **可实现性**：公式与 Python/MATLAB 工具一致。
- **可追溯性**：参数、阈值和假设有来源。
- **创新性**：创新能映射到具体实现和验证。

### 6.7 验证方式

可按模型选用留出集、滚动回测、残差诊断、约束可行性、最优性界、稳定性、灵敏度、消融实验和外部数据对照。所有检验阈值必须写明依据。

## 7. 11 种常见模型组合模式

### 7.1 优化类

1. **线性/整数规划 → 灵敏度分析**：用于资源分配、生产调度和投资组合；输出最优解、影子价格和灵敏度范围。
2. **启发式算法 → 对比验证**：用于 TSP、VRP、调度等大规模 NP-hard 问题；用小规模精确解、文献结果或其他启发式作对照，并输出收敛曲线。
3. **多目标优化 → Pareto 分析**：用 NSGA-II、MOEA/D 或加权和法形成 Pareto 前沿，可再用 TOPSIS 选择折衷方案。

### 7.2 预测类

4. **单一预测 → 误差检验**：适合小样本或趋势明显数据；可用 GM(1,1)、线性回归、指数平滑，并做残差、后验差和相对误差检验。
5. **双模型对比或集成预测**：从 ARIMA、LSTM、XGBoost 等中选两个有差异的模型；先比较误差，有依据时再加权集成。
6. **组合预测（串联）**：先分类后预测或先分解后预测，例如聚类→分群回归、STL→ARIMA。

### 7.3 评价类

7. **赋权 + 综合评价**：AHP 或熵权确定权重，配合 TOPSIS、灰色关联或模糊综合评价，最后做权重扰动与排名稳定性分析。
8. **DEA 效率评价**：CCR/BCC 评价多投入多产出效率，并结合投影分析、规模收益和改进目标。

### 7.4 综合类

9. **优化 + 模拟**：蒙特卡洛生成不确定场景，优化模型逐场景求解，输出解的分布及 VaR、CVaR 等风险指标。
10. **评价 + 优化**：先识别薄弱环节，再针对关键因素优化资源配置。
11. **预测 + 决策**：先预测未来需求或状态，再进行库存、交通或调度优化。

## 8. 编程手：完整职责

### 8.1 输入

优先读取：

- 题目附件；
- `题目分析报告.md`；
- `术语表格.md`。

如果用户只做编程阶段，可以从用户提供的模型说明开始；若公式、约束、参数或输入输出不足以实现，应明确反馈缺项。

### 8.2 固定交付物

- 可运行的 Python `.py` 或 MATLAB `.m`；用户要求时可同时提供两套。
- `results/` 中的真实运行表格和必要文本结果。
- `figures/` 中三类图：原始数据图、模型运行过程图、模型最终结果图；允许生成多个候选版本。
- `results/复现清单.json`。

### 8.3 语言选择与动态依赖

按用户要求、现有项目和模型依赖选择 Python/MATLAB。没有偏好时按现有环境和模型函数选择并说明。缺依赖时报告精确包或工具箱名称，不能自动换成另一个模型或语言。

Python 支持按功能检查：

- `data`
- `visualization`
- `excel`
- `optimization`
- `integer-optimization`
- `statistics`
- `machine-learning`
- `time-series`
- `graph`
- `image`

MATLAB 常见映射：

| 功能 | 工具或工具箱 |
|---|---|
| 线性、非线性、整数优化 | Optimization Toolbox |
| 统计、回归、分类、聚类 | Statistics and Machine Learning Toolbox |
| 时间序列与计量 | Econometrics Toolbox |
| 符号推导 | Symbolic Math Toolbox |
| 图论与基础可视化 | MATLAB 基础环境 |

### 8.4 编码和运行规范

- 数据读取、预处理、模型、验证、可视化和输出拆成清晰函数。
- 随机算法显式设置种子。
- 关键参数集中定义并进入复现清单。
- 必须真实运行代码，检查退出状态与异常。
- 检查约束可行性、边界条件、量纲、数值范围和验证指标。
- MATLAB 使用 `fullfile` 构造路径、`arguments` 校验输入、`rng(seed,"twister")` 固定随机性；优化必须检查 `exitflag` 和约束残差。

### 8.5 复现清单

必须记录：

- 随机种子；
- 输入文件 SHA-256；
- Python 或 MATLAB 运行时版本；
- 实际使用的依赖或 MATLAB 工具箱版本；
- 关键参数；
- 唯一复现命令；
- 输出位置。

唯一命令应能从 `PROJECT_ROOT` 直接执行，并重新生成论文引用的表格和图。

### 8.6 Excel 规则

- 普通结果汇总优先 CSV。
- 只有题目要求 `.xlsx`、需要多工作表、保留公式或既有模板时才用 XLSX。
- 明确声明表头；第一行就是数据时必须 `header=None`，禁止默认 `header=0` 吞掉第一行。
- 核对首行、末行、有效行数和题目声明记录数。
- 不随意删除未知工作表、命名区域、公式或数据验证。
- 修改公式工作簿后用隔离 LibreOffice 重算；失败或超时不能覆盖原文件。

## 9. 可视化规范

### 9.1 三类图

1. **原始数据图**：分布、时间趋势、空间结构、相关性、异常点。
2. **模型过程图**：收敛、训练、残差、灵敏度、消融、约束状态。
3. **模型结果图**：方案、预测、排名、误差、不确定性。

候选图数量不设上限，但每张图都必须数据正确、标题清楚、坐标与单位明确。

### 9.2 通用硬规则

- 默认不使用网格线。
- 项目内颜色语义一致，并兼顾色觉可达性。
- 同时保存 SVG 和 300 DPI PNG，不能只 `show()`。
- 统计量、置信区间和 p 值必须由当前数据计算，禁止硬编码。
- 置信区间不能用标准差冒充。
- 特殊参考线只能用有明确数值意义的 `xline`、`yline` 或零线，并在图注解释。
- HTML 面板与图在同一 `figures/` 目录时，资源路径用文件名或 `./文件名`。

### 9.3 11 种图表模式

1. 分组柱状图：多方法、多指标对比。
2. 堆叠柱状图：组成结构、占比、资源分配。
3. 趋势线 + 置信区间：时间趋势、预测和收敛不确定性。
4. 多线对比：不同算法、不同参数的变化过程。
5. 热力图：相关矩阵、混淆矩阵、Z-score 偏差。
6. 气泡图：同时表达三个维度。
7. 散点 + 拟合线 + 象限：相关性、分类和 Pareto 分析。
8. 箱线图：分布、离群值、误差和稳定性。
9. 图例专用轴：解决多图例遮挡。
10. 面板标签和统计标注：规范多子图标识与结果注释。
11. 色深对比判断：根据背景亮度自动选择深色或白色文字。

### 9.4 HTML 图表面板

内置模板提供：左侧导航、图号与描述、SVG 加载、缩放、重置、SVG/PNG 导出、全屏、上下键切换、Ctrl+滚轮缩放，以及 `Ctrl++`、`Ctrl+-`、`Ctrl+0`、`Ctrl+E`、`F11` 快捷键。模板需复制到项目后按实际图文件动态生成导航项。

- 可运行代码；
- 实际运行结果表格；
- 三类真实图；
- 已核验文献元数据。

缺少关键输入时回退对应角色，不得猜数值、伪造图表或编造引用。

### 10.4 Claim-Evidence 映射

写作前在内存或临时工作区建立“主张—证据”映射。每个核心结论必须对应至少一种证据：

- 数学公式；
- 代码输出；
- 结果表格；
- 图；
- 经核验文献。

### 10.5 推荐章节逻辑

官方模板优先；若官方未固定章节，可按以下结构组织：

1. 标题与摘要页；
2. 问题重述与问题分析；
3. 模型假设与符号说明；
4. 各子问题的模型建立、求解、验证和结果；
5. 灵敏度、稳健性或误差分析；
6. 模型评价与适用边界；
7. 参考文献；
8. 官方允许或要求的附录。

每个子问题推荐按“变量与参数 → 假设依据 → 数学定义 → 算法 → 运行参数 → 实际结果 → 验证”展开。

### 10.6 写作规则

- 术语和符号严格服从 `术语表格.md`。
- 每段围绕一个明确论点，先给事实或推理，再解释含义。
- 数值、单位、公式、图号、表号和引用前后一致。
- 不使用“专家认为”“效果显著”等无来源表达。
- 不用宣传性语言代替证据。
- 不虚构数据、实验、文献或官方要求。
- 模型优点、局限、失败条件和适用边界必须具体可追溯。

### 10.7 英文 MCM/ICM 工作流

核心原则是“翻译意图和论证，不逐字翻译句序”。分三步：

1. **理解**：把中文素材提炼为 Problem、Method、Result、Comparison 等论证结构。
2. **写作**：按英文学术语篇重构摘要和正文，具体数据替代“具有良好效果”等空话。
3. **校准**：依次检查论证准确性、中式英语和动词强度。

动词强度应与证据匹配：

- 直接数值证据：`show`、`demonstrate`、`establish`；
- 趋势证据：`suggest`、`indicate`、`reveal`；
- 理论或不确定推断：`may`、`could`、`appear to`；
- 避免无充分证据使用 `prove`、`verify`、`will`。

### 10.8 CUMCM 页数与篇幅口径

- 以 2026 官方规范为例：摘要原则上不超过一页，正文不超过 30 页。
- 内置的约 15000 字词单位、约 20 页，是防止论文过短的**完整度质量目标**，不是官方最低要求，可以被当届规则或用户要求覆盖。
- 页数必须以 DOCX 渲染后的实际页数为准，不能根据字符数猜测。
- 默认的 5 个公式、3 幅图、3 个表同样是质量检查目标，不是机械硬指标；最终应服从论证实际需要与官方规则。

### 10.9 Word 构建要求

- 从当届官方模板构建；保留样式、分节、页眉页脚和页面设置。
- 官方模板有固定摘要页、编号页或占位符时，保留内容并原位填充。
- 如果仅借样式，则清除示例正文，不能把模板示例留在论文中。
- 公式必须是 Word 原生可编辑 OMML，不能是截图或纯文本 LaTeX。
- 表格必须是可编辑 Word 表格，三线表可用工具函数生成。
- 每幅图和每个表都要有连续编号、题注，并在正文至少引用一次。
- 参考文献条目与正文引用双向对应，DOI 和出版信息需核验。

## 12. 四个集成工具

### 12.1 双引擎论文搜索

数据源：

- OpenAlex：结构化学术元数据；
- AnySearch Academic：学术垂直搜索。

正式检索默认并行运行两个引擎。融合规则：

- DOI 相同直接视为交叉验证；
- 无 DOI 时，仅在题名高度相似且年份相容时合并；
- 同一引擎内题名相同的预印本与正式版会折叠，优先保留元数据更完整者；
- 结果分为交叉验证、OpenAlex 独有、AnySearch 独有；
- 按查询词覆盖率过滤和重排，相关性优先于引用量；
- 多专业术语查询通常至少命中两个有效查询词，但仍需人工核验；
- 物理、材料、光学查询应组合材料名、机理名和模型名，结果少时逐步放宽。

核验原则：搜索结果只用于发现候选；引用前必须打开 DOI 或出版页面核对作者、题名、年份、期刊/会议、卷期页；不能把引用量当作正确性证明，也不能根据标题或摘要编造结论。

- pypdf 读取、合并、拆分、旋转、元数据、加密和水印；

- pdftotext、qpdf、pdftk 等命令行操作；
- 扫描 PDF 转图后 OCR；

- AcroForm 字段检测、结构提取、填写、坐标转换与验证图。

ReportLab 特别约束：不要直接使用 Unicode 上下标字符，以免内置字体显示黑框；段落中应使用 `<sub>`/`<super>` 标记。

### 12.3 Excel 工具

支持 XLSX 读取、创建、修改、模板保留、公式重算和错误检查。关键安全点：

- 输入只读，输出写入项目目录；

### 12.4 DOCX 工具

支持：

## 16. 使用边界与应注意的口径

1. **官方规则永远优先**：Skill 内的 CUMCM 配置和模板不能替代当届官方文件。
2. **15000 字、20 页不是官方最低要求**：它们只是默认完整度目标。
3. **算法资料是参考，不是自动选型器**：每次仍需检查假设、数据、规模、目标和依赖。
4. **搜索结果不是最终引用**：必须打开 DOI 或出版机构页面复核。
5. **复杂不等于创新**：复杂模型若不适配题目，反而降低可解释性和可靠性。
6. **候选图可以很多，但论文图应服务论证**：最终由用户和论文手按叙事选择。
7. **XML 校验不等于视觉正确**：DOCX 还必须渲染检查。
8. **单阶段任务不扩张范围**：只分析就只交两个 Markdown；只写论文必须先确认真实输入是否完整。
9. **内置历史更新记录不等于当前能力**：`CHANGELOG.md` 的“版本号重置前历史”仅说明旧版本曾经发生的事，当前能力以 1.0.0 主文件、角色文件和实际脚本为准。
10. **算法库 README 中“蒙特卡洛几乎必用”等表述只能当经验性提示**：实际主规则仍是按题目结构选择模型，不能机械套用。

`math-modeling` 不是一个“自动套模型写论文”的 Skill，而是一套以**题目理解、模型契约、真实运行、可复现证据、官方模板和严格验证**为核心的数学建模工程流程：建模手负责把问题定义正确，编程手负责把模型真实算出来，论文手负责只用可追溯证据完成规范 Word 论文。
