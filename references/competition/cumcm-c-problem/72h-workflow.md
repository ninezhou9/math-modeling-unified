# 国赛 C 题 72 小时工作流

## 0–3h：选题与读题
- 三人独立读 C 题，再合并理解。
- 建立问题依赖图。
- 审计附件字段、规模、时间范围。
- 判断：统计/预测/分类/规划/混合。
- 产出：一页“模型主线草图 + 风险点”。

## 3–10h：问题一地基
- 完成数据清洗与高价值 EDA。
- 先做最简单可解释基线。
- 确定核心指标和后续接口。
- 同步写问题重述、分析、假设、符号。
- 至少生成2–4张真正有结论的图，而不是批量画图。

## 10–24h：中间问题与第一次成型
- 推进 Q2/Q3；优先复用 Q1 的参数和结构。
- 每问都完成“数学模型总括框”。
- 建立完整结果表。
- 若模型升级，记录“基础法失效证据”。
- 第一晚必须有一版能回答所有已完成问题的正文，不等待最后再写。

## 24–40h：优化/高级问题
- 处理最难的一问或优化问题。
- 若需要高级算法，此时再引入。
- 同时做一般化、复杂度或结构化简。
- 设计一张真正能展示创新的策略相图/决策热力图/网络图/风险图。

## 40–52h：不确定性与验证
- 核心模型至少一个独立验证。
- 做参数敏感性或 Bootstrap/Monte Carlo。
- 若最终是决策，检查误差是否会改变策略。
- 补“为什么结果合理”的文字证据。

## 52–62h：论文呈现
- 重写摘要，不从正文自动拼接。
- 重新设计 overview 图。
- 统一图表颜色、字体、单位、小数位。
- 把关键目标函数与约束集中成方程组。
- 检查段落是否每段都有作用。

## 62–68h：页数与参考文献
- 主论文压到25–28页目标区间（官方规则允许时）。
- 删重复而不是缩字体。
- 补真实领域文献、标准、数据来源、方法来源。
- 附录列文件清单。

## 68–72h：三轮审稿

### 数学审稿
公式、单位、边界、代码结果。

### 评委审稿
只看摘要、总览图、每问模型框、最终结果表，是否能理解主线与创新。

### 排版审稿
逐页看 PDF：孤行、溢出、图表大小、caption、空白、颜色、参考文献和第一页。
