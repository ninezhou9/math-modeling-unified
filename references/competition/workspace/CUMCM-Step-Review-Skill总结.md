# CUMCM Step Review Skill 总结

> 来源：`C:\Users\qwerq\.codex\skills\cumcm-step-review\SKILL.md`  
> 用途：快速理解 `cumcm-step-review` 的目标、执行流程、质量门禁和交付要求。  
> 本文是摘要，不替代原 Skill；执行任务时仍以原文件和当届官方竞赛规则为准。

## 1. Skill 定位

`cumcm-step-review` 是面向全国大学生数学建模竞赛（CUMCM）的分步审核工作流，适用于：

- 国赛题目理解与问题重述；
- 数据预处理；
- 模型选择、算法设计和代码求解；
- 结果可视化与误差检验；
- 分章节撰写数学建模论文；
- 生成最终 Word、PDF、LaTeX 工程和复现材料。

它的核心特点不是一次生成整篇论文，而是让每个部分依次经历：

```text
分析 → 方案审核 → 代码实现 → 写入论文草稿 → 用户审核 → 冻结
```

未经用户审核的部分不能冻结，也不能直接进入下一部分。

## 2. 根目录与文件安全

| 名称 | 作用 | 规则 |
| --- | --- | --- |
| `SKILL_ROOT` | Skill、脚本、参考资料和模板所在目录 | 只读，默认禁止覆盖 |
| `PROJECT_ROOT` | 当前竞赛项目目录 | 所有新产物只能写入这里 |
| 输入附件 | 题目、数据和模板等输入文件 | 默认只读，需要修改时先复制到项目目录 |

`SKILL_ROOT` 与 `PROJECT_ROOT` 必须不同，避免把用户项目产物写进 Skill 本身。

## 3. 强制执行协议

1. 首次更新必须说明：已启用的 Skill、两个根目录、当前论文部分、目标赛题与届次、准备读取的入口。
2. 开始某一论文部分前，必须实际读取 `references/阶段流程.md` 对应章节。
3. 写入论文草稿前，必须读取优秀论文写法指南；摘要、图表、PDF、Excel、DOCX、LaTeX和论文搜索等任务还要加载对应专用说明。
4. Skill 已有脚本或模板时，应优先调用，不能为了省事重新手写替代品。
5. 校验警告视为未完成；除非官方规则或用户明确允许，不得自行降低质量标准。
6. 工具或依赖缺失时，需要报告阻塞，同时继续完成仍可验证的部分，不能静默换用低质量方案。
7. 每个论文部分写入 `论文草稿.docx` 后都要交给用户审核；用户确认后才冻结。
8. 关键节点执行作者自检；独立 Subagent 质检默认关闭，只有用户明确启用时才执行。
9. 交付前必须运行当前部分的全部完成门禁，不能只口头声称“已检查”。

## 4. 分步审核流程

Skill 按以下顺序推进：

1. 问题重述；
2. 数据预处理；
3. 各子问题的建模与求解（问题一到问题 N）；
4. 模型分析与检验；
5. 模型评价与推广；
6. 参考文献；
7. 附录；
8. 问题分析；
9. 模型假设；
10. 符号说明；
11. 摘要。

其中问题分析、模型假设和符号说明在问题确定后撰写；摘要必须等全部正文冻结后再写，并执行“起草→二次验证→定稿”的闭环。

## 5. 不同用户需求的处理方式

| 用户需求 | 执行方式 |
| --- | --- |
| 完整数学建模 | 按完整分步流程推进，全部审核后生成最终论文 |
| 只做某一章节 | 只执行该章节及其必要门禁 |
| 只写代码或跑结果 | 必须先具备清楚的题目与模型说明 |
| 只生成或修改论文 | 必须使用已经审核的草稿和真实运行结果；不足时回退到对应建模步骤 |

## 6. 固定交付物

完整任务通常包括：

- `论文草稿.docx`：分步骤追加，供用户审核；
- `完整论文.docx`：全部内容审核冻结后生成；
- `完整论文.pdf`；
- `完整论文-LaTeX/`；
- 可运行的 Python 或 MATLAB 代码；
- 结果表格；
- 原始、过程和结果三类候选图；
- `results/复现清单.json`；
- 支撑论文写作的内部分析文件。

论文草稿必须是可直接阅读和批注的 Word 文档，不能用 Markdown 代替正式审核载体。

## 7. 模型选择约束

1. 必须先理解题目、附件、目标、约束和评价口径，再确定模型。
2. 每个子问题最多使用两个独立模型体系。
3. 同一机理在不同精度、阶段或边界条件下的展开，仍视为同一模型族。
4. 灵敏度分析、误差检验和可视化属于辅助验证，不单独计算模型数量。
5. 不能用常见简单模型冒充创新；创新应来自问题结构、数据处理、约束、算法改进或验证方式。
6. 判定标准必须来自题目、官方规则、领域文献或数据分析结果。
7. 是否保留对照模型取决于研究目的和证据价值，不能仅因结论相近就强制删除。

## 8. 图表硬性规范

- 图内不能出现标题或面板编号，标题信息统一放在图注中；
- 图题放在图下方；正文遵循“先引导→插图→紧随分析”；
- 连续两张以上图表之间必须有解释文字；
- 图中文字按最终印刷尺寸设置，正文标签建议 8.5–11 pt，最小不低于 7.5 pt；
- 同一图型不宜在全文超过三张，也不宜连续出现三张以上；
- 默认使用期刊风格配色，需要严格色盲友好时使用 `okabe-ito`；
- 禁止机械使用默认 2×2 布局，应根据证据权重选择布局；
- 数据图默认导出 300 DPI PNG，可按需增加 SVG、灰度预览或其他格式；
- 技术路线图、流程图、模型结构图等非数据图统一使用 Skill 内置 draw.io 工具生成，并保留 `.drawio` 源文件。

## 9. 渐进式工具加载

Skill 不允许一次性加载全部资料，而是按任务读取对应入口：

| 当前任务 | 需要读取的主要入口 |
| --- | --- |
| 开始某个论文部分 | `references/README.md`、`references/阶段流程.md` |
| 写入论文草稿 | 优秀论文写法、写作与图表规范、章节模板 |
| 写或评摘要 | 摘要写作方法论及配套检查资料 |
| 模型选择 | `references/模型选型树.md`、`references/算法索引.md` |
| 数据图绘制 | 图表知识库、图型选择、绘图样式脚本 |
| 流程图或技术路线图 | draw.io 流程规范与工具说明 |
| 文献搜索 | 双引擎论文搜索 Skill |
| PDF、Excel、Word、LaTeX | 分别读取对应工具的 `SKILL.md` |
| 最终验收 | `scripts/paper_check.py`、`references/质检清单.md` |

## 10. 质量门禁

质量控制分为三层：

1. **作者自检**：每个部分冻结前按质检清单检查；
2. **用户审核**：硬性门禁，未通过不能冻结；
3. **最终验收**：全部内容冻结后，检查代码结果、公式、表格、图表、引用、编译和页面质量。

Word 分支重点检查：

- 原生公式结构；
- DOCX 文档结构；
- 转换告警；
- 渲染页数与视觉效果。

LaTeX/PDF 分支重点检查：

- 环境和真实编译；
- 编译日志；
- 源码与PDF哈希绑定；
- 页数、空白页和页面尺寸；
- 字体嵌入和图片DPI。

## 11. 完成标准

只有同时满足以下条件，才能宣称任务完成：

- 所有要求的论文部分已写入 Word 草稿并通过用户审核；
- 所有计算结论来自真实运行结果；
- 代码、公式、表格、图表和论文中的数值完全一致；
- 引用可以追溯，参考文献与正文引用双向对应；
- 摘要与每个子问题一一对应，并包含经过核对的量化结果；
- 论文符合当届官方格式和页数要求；
- Word、LaTeX和PDF均通过对应的结构、编译和视觉检查；
- 所有产物位于 `PROJECT_ROOT`，且 `SKILL_ROOT` 未被改写。

## 12. 一句话理解

`cumcm-step-review` 的本质是：

> 用“逐部分分析、用户双重审核、真实代码结果、严格质量门禁”的方式完成一篇可复现、可校验的CUMCM数学建模论文，而不是一次性生成未经验证的全文。
