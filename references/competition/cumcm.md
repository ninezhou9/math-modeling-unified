# CUMCM 通用规则

本文件适用于所有全国大学生数学建模竞赛（CUMCM）任务。确认为 CUMCM 任务后加载，非 CUMCM 任务不读取。

```yaml
routing:
  generic_math_modeling: []
  cumcm_undergraduate_a: ["cumcm"]
  cumcm_undergraduate_b: ["cumcm"]
  cumcm_undergraduate_c: ["cumcm", "c_problem"]
  cumcm_undergraduate_d: ["cumcm"]
  cumcm_undergraduate_e: ["cumcm"]
authority_order:
  - current_official_problem_rules_templates
  - cumcm_published_regulations
  - unified_skill_guidance
  - historical_experience
unknown_current_requirements: pending_verification
historical_guidance: non_binding
```

## 规则优先级

1. **当届赛题官方规则与官方模板**（最高优先级）：包括赛题文件中关于格式、章节、AI 使用声明、支撑材料和交付物的明确要求。
2. **CUMCM 组委会公开规程**：包括参赛须知、评审标准说明等官方文件。
3. **统一 Skill 指导**：本文件及其引用的内部模块。
4. **历史经验**：往届赛题与论文总结，仅作为参考，不得覆盖当届官方要求。

未从当届官方来源确认的规则统一标为"待核验"，不得将历史经验直接写成现行要求。

## 赛题分析与建模

### 题意理解

- 完整阅读赛题、附件、数据和补充说明后再形成任何结论。
- 区分"题目明确要求"与"分析后的推断"，后者需标注推断依据。
- 每道子问题的目标、输入、输出、约束和评价口径必须显式列出。

### 模型选择约束

- 每道子问题最多两个独立模型体系；同一物理机制在不同近似阶段、边界条件或精度下的展开计为一个模型族。
- 只有控制机理、状态变量或求解目标实质不同才另计模型。
- 辅助的灵敏度分析、误差检验和可视化不计作独立模型。
- 创新必须来自问题结构、数据处理、约束设计、算法改进或验证方式，并说明依据；避免直接套用过于常见的简单模型冒充创新。

### AI 使用声明

当届赛题如要求填写 AI 使用情况说明，必须如实填写；未确认是否需要时标为"待核验"，不得遗漏。

## 支撑材料与交付物

### 支撑材料要求

- 当届赛题如要求提交支撑材料（代码、数据、中间结果等），按官方规定的格式和命名交付。
- 未确认支撑材料要求时标为"待核验"。

### 论文章节结构

论文章节顺序以当届官方模板为准。通常包含：

1. 摘要（含关键词）
2. 问题重述（问题背景、问题提出）
3. 问题分析
4. 模型假设
5. 符号说明
6. 模型建立与求解（按子问题分节）
7. 模型的分析与检验
8. 模型的评价与推广
9. 参考文献
10. 附录

但最终以当届官方规则与模板为准；官方要求与此列表不同时，按官方执行。

## 图表规范

- 图内不允许出现任何标题（图上方、图下方均不写），也不画面板编号，只保留数据。
- 图题（caption）放在图下方；正文"先引导 → 插图 → 紧随其后的分析"，连续两张以上图表之间没有文字判为硬错误。
- 图中文字按最终印刷尺寸设定（正文标签 8.5–11pt，最小 ≥ 7.5pt），禁止缩放导致图大字小。
- 图型多样性：同一类型图全篇不宜超过 3 张，同类图不连续出现 3 张以上。
- 配色使用期刊色板（nature / science / cell / ieee / okabe-ito / wong 等），默认 nature，需严格色盲友好时用 okabe-ito。
- 非数据图（技术路线图、流程图、模型结构图）用 draw.io 制作，规则同上。

## 分步审核与冻结

按逐步审核工作流执行：每部分先分析与方案，用户审核后代码实现，写入论文草稿.docx 再次用户审核，冻结后进入下一部分。详见统一入口中链接的逐步审核与冻结工作流。

## 质量门禁

- 作者自检：每部分冻结前完成自检。
- 用户审核：硬性门禁，未通过不得冻结。
- 最终验收：全部冻结后运行完成门禁，硬错误未修不得交付。

## 交付物清单

1. `论文草稿.docx`：分步追加、供用户审核的 Word 文档。
2. `完整论文.docx`：全部审核定稿后生成。
3. `完整论文.pdf` 与 LaTeX 源文件：由同一冻结正文生成并真实编译。
4. 可运行代码（`.py` / `.m`）、结果表格、分类候选图、`复现清单.json`。
5. 当届要求的支撑材料（待核验）。
