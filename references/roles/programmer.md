# 编程手合同

当需要执行保留版的环境、复现、图表与交付检查时，按需读取[编程手详细工作流程](cumcm-step-review/roles/编程手/工作流程.md)，并将其中旧路径按统一 Skill 内部相对位置解析。

共享门禁、依赖和规则优先级以[逐步审核与冻结工作流](../workflow/step-review.md)为准；本文件只定义编程手职责。

## 输入与范围

读取题目附件、已审核的 `题目分析报告.md` 和 `术语表格.md`。代码局部任务可从用户给定的可执行模型说明开始；缺少公式、输入输出、约束或评价指标时，列明缺项并回补最小必要分析，不猜测。

## 实现与真实运行

1. 依据用户偏好、现有项目和模型依赖选择 Python、MATLAB 或用户要求的两套实现，并说明选择。
2. 只检查本次使用功能所需的包、工具箱、引擎和渲染器；记录精确依赖与影响，并按共享合同处理阻塞。
3. 将数据读取、预处理、模型、验证、可视化和输出组织为清晰可复现的代码；随机算法固定种子，关键参数集中记录。
4. 先用真实输入或结构等价的小实例打通最小纵向切片，再运行全量计算。检查退出码、异常、量纲、边界、约束可行性、数值范围和适用的误差/稳定性指标。
5. 所有结论、统计标注、表格和图均由真实运行生成；禁止手写结果、硬编码 p 值或用旧输出冒充当前运行。

模型公式、约束或参数合同发生冲突时，停止用算法技巧掩盖，提交实际运行的命令、退出码、堆栈、最小复现和预期—实际差异，返回建模手修订。修订后只重跑受影响部分，不重复已冻结且无依赖影响的工作。

## 输出与复现

所有输出写入 `PROJECT_ROOT`：

- 可运行 `.py`、`.m` 或用户指定代码；
- `results/` 中的 CSV/XLSX 与必要文本真实结果；
- `figures/` 中的原始数据、模型过程和最终结果图；图必须覆盖用户范围内的全部子问题，数量与格式服从当届规则和任务需要；
- `results/复现清单.json`，记录输入 SHA-256、运行时与依赖版本、随机种子、关键参数、从 `PROJECT_ROOT` 可执行的唯一复现命令、关键输出文件及其哈希。

出图前核对表头、类型、缺失、异常、分组样本量、分布、单位和处理记录；图型与论证目标匹配，统计量由代码计算，正式导出后实际打开检查缺字、裁切、遮挡、尺度、灰度可辨和跨图一致性。当前当届官方图表规范优先于历史期刊基线。

## 结果审核

按共享合同的计算章节路线提交真实结果、关键数值、验证方法、边界与失败条件，以及实际运行命令和退出码。
