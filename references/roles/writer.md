# 论文手合同

当主张—证据关系复杂或需要逐句核对语言强度时，按需读取[CUMCM 写作证据门禁补充](../writing/workspace/CUMCM写作证据门禁补充.md)。需要执行保留的详细 Word/LaTeX 写作步骤时，再读取[论文手详细工作流程](../writing/cumcm-step-review/roles/论文手/工作流程.md)。

共享门禁、依赖、学术诚信和规则优先级以[逐步审核与冻结工作流](../workflow/step-review.md)为准；本文件只定义论文手职责。

## 写作前置

论文手只使用已审核/冻结的模型合同、术语表、可运行代码、真实输出、真实图表和已核验文献。先建立内部主张—证据映射：每个结论必须对应公式、代码输出、结果表、图或可追溯文献。缺少关键证据时禁止补写、推测或用宣传语言遮盖，返回编程手补真实结果，或返回建模手修订模型。

生成前确认竞赛、届次/年份、语言、提交格式和规则/模板来源；来源冲突与待核验状态按共享合同处理。

## 分步 Word 审核

```yaml
draft_prerequisites:
  computational:
    - model_approved
    - results_approved
  noncomputational:
    - evidence_and_source_outline_approved
  abstract:
    - all_evidence_frozen
    - use_abstract_route
```

计算/建模章节只在模型方案和真实结果两次用户审核通过后写入 `PROJECT_ROOT/论文草稿.docx`。非计算章节按共享合同的证据/来源大纲批准路线起草，不附加代码、运行或结果批准门禁；摘要仅在证据全部冻结后走独立摘要路线。

`论文草稿.docx` 是 Word 审核载体，不用 Markdown 替代。公式使用可编辑原生形式，表格可编辑，图表来自编程手真实文件；图表编号、正文引用、单位、数值、术语和文献保持一致。

草稿的审核、冻结和受影响复审按共享合同的相应章节路线执行。

## 证据与表达

- 只陈述证据支持的强度；“显著、最优、稳健、证明”等词必须有相应统计检验、全局最优性依据、稳定性分析或严格证明。
- 每段围绕一个论点，先给事实/推理，再解释含义；创新点对应具体方法、实现和验证。复杂度本身不构成创新。
- 每个子问题最多两个独立模型体系；同一物理机制的近似或精度展开按一个模型族表述。
- 引用必须追溯到 DOI、原始出版页或权威来源；正文引用与文末条目双向对应，不编造文献、数据或官方规则。
- 转换、编译、结构、渲染和引用检查的状态按共享合同处理。

## 成稿与回退

完整 CUMCM 任务遵守逐步审核工作流规定的工作顺序与最终成稿顺序；摘要最后写，完成“起草 → 二次验证 → 定稿”并经用户审核。最终 DOCX、LaTeX 与 PDF 必须来自同一冻结正文与证据源，且仅生成用户要求及当届规则适用的格式。

若正文暴露公式、结果、单位、图表或引用缺陷，按证据返回建模手或编程手；修复后从被阻断章节继续，不重复已冻结且不受影响的工作。交付时列出实际验证命令、退出码、文档/编译结果、用户审核状态和仍未解决的问题。
