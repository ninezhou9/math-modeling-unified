# 优秀论文语言风格、模型构建方法与 Skill 补充建议

## 一、分析范围

本报告不讨论论文模板、章节格式、字体、页数和图表排版，只分析：

1. 优秀论文怎样表达建模过程；
2. 模型怎样从题意逐层构建出来；
3. 现有数学建模 skill 在这两方面还缺什么。

文件夹内共有 152 份 PDF。排除赛题和格式规范后识别出 139 份论文候选，其中 106 份能够直接抽取足量文本。分析覆盖 2001 年早期论文、2015—2018 年论文和 2023 年 A/B/C 类展示论文。扫描版只用于辅助判断，不把文本抽取失败解释为论文没有某项内容。

## 二、优秀论文的语言风格

### 1. 用动作和证据推进，不用评价性语言推进

优秀论文最常见的表达逻辑是：

> 根据什么 → 做了什么 → 得到什么 → 说明什么

常用实义动词包括“定义、引入、推导、建立、约束、代入、求解、比较、检验、得到”。这些动词承担建模动作。较少使用“非常有效、十分合理、具有重大意义”等无法直接验证的表述。

例如，好的结果段不会只写“模型效果较好”，而会写明误差、最优值、排序变化、约束满足情况或与基准方案的差异，再据此作出判断。

### 2. 每句话承担明确功能

优秀论文中的句子大致可以分为七类：

| 句子功能 | 回答的问题 | 典型表达 |
|---|---|---|
| 对象定义 | 研究什么 | “将……定义为……，记为……” |
| 选择依据 | 为什么这样建模 | “考虑到……具有……特征，因此采用……” |
| 关系推导 | 变量怎样联系 | “由……关系可得……，进而……” |
| 模型封闭 | 还需要什么假设或条件 | “在……假设下，结合边界条件……” |
| 求解说明 | 怎样得到结果 | “固定……后，采用……算法求解……” |
| 结果报告 | 算出了什么 | “求得……为……；对应方案为……” |
| 结果解释 | 结果说明什么 | “这表明……，其原因在于……” |

较弱的论文容易把这些功能混在一个超长句中，或者连续介绍算法原理却迟迟不回答题目。

### 3. 主语明确，少用空泛代词

近年论文更偏好用“本文、该模型、目标函数、约束条件、计算结果”作为主语。按抽取文本每万字符粗略统计：

| 时期 | “本文” | “我们” | “首先” | “因此” | “建立” |
|---|---:|---:|---:|---:|---:|
| 2001 | 2.73 | 21.15 | 2.23 | 1.98 | 6.02 |
| 2015—2018 | 4.70 | 17.75 | 4.86 | 4.46 | 14.40 |
| 2023 | 5.68 | 12.47 | 6.79 | 6.18 | 13.59 |

这说明“我们”可以使用，但近年优秀论文更倾向于客观、明确的主语。应避免反复出现“我们认为、我们发现、我们可以看出”，改为指出是谁产生了什么证据，例如“计算结果显示”“残差图表明”。

### 4. 连接词用于展示推理层级

“首先、其次、接着、最后”主要组织求解步骤；“由于、因此、从而、进而”主要组织因果推导；“在问题一的基础上”说明子问题依赖。

连接词后必须有真正的逻辑关系。连续使用“首先—其次—最后”罗列模型名，不属于有效推理。

### 5. 数值与判断绑定

优秀论文不孤立罗列数据，也不孤立给出判断。常见结构是：

> 指标值或变化量 + 对比基准 + 判断 + 实际含义

“显著、稳定、合理、有效、较优”等词只有在统计检验、误差、敏感性、可行性或基准比较支撑下才成立。

### 6. 公式前后都有自然语言

关键公式出现前，先说明要描述的对象和关系；公式之后解释符号、来源和用途。优秀论文不是“公式堆”，而是“语言提出关系—公式精确定义—语言解释含义”。

### 7. 摘要与正文语言层级不同

摘要使用“问题—方法—结果—结论”的高密度表达；正文需要展开选择依据、推导过程、参数来源和验证过程。不能把摘要式的模型名罗列直接扩充成正文。

### 8.图表解释
不要逐项复述图表，只提炼最明显的2—4个特征；先写数据事实，再写比较关系，最后解释现实含义 不只是简单复述而是解释数据表达的内容

## 三、优秀论文如何构建模型

### 1. 先确定每问要输出什么

优秀论文首先识别子问题最终需要的是数值、函数关系、分类、排序、路径、调度方案还是决策规则。输出类型确定后，才决定需要哪些状态变量、约束和评价指标。

这一步决定模型边界，能够防止“看到数据就聚类”“看到预测就 LSTM”式套模。

### 2. 把题目对象翻译成数学对象

常见翻译包括：

- 实体变为点、集合、节点、决策单元或样本；
- 行为变为状态转移、流量、控制量或决策变量；
- 空间关系变为距离、角度、邻接关系或坐标变换；
- 规则变为等式、不等式、逻辑约束或边界条件；
- “好坏”变为目标函数、损失函数或评价指标。

优秀论文会明确解释“题目元素—模型元素”的对应关系，而不是直接写出一个现成模型。

### 3. 先建立骨架关系，再补充细节

模型通常按以下顺序形成：

1. 定义研究对象、变量和坐标或时间尺度；
2. 写出最基本的几何、物理、统计或业务关系；
3. 加入题目给出的规则和约束；
4. 识别仍未闭合的未知关系；
5. 用假设、经验关系、数据拟合或文献参数完成闭合；
6. 得到可计算的完整模型。

这一顺序在机理题中表现为“受力/几何关系—控制方程—边界条件”，在优化题中表现为“变量—目标—约束—可行域”，在数据题中表现为“数据口径—特征—响应—损失—验证”。

### 4. 模型由题目结构自然生长，而不是从算法表中挑选

优秀论文常先建立问题专属的关系，再选择数值算法求解。算法是求解器，不等于模型本身。

例如：

- 先根据空间遮挡关系构造有效性判据，再用搜索算法优化参数；
- 先由业务规则写出库存、价格和利润关系，再使用优化算法求最优方案；
- 先确定指标含义和数据生成机制，再选择回归、分类或时间序列方法。

### 5. 从基础模型逐层改进

优秀论文经常先构造可解释、可检查的基础模型，再针对误差来源加入修正：

- 从二维关系推广到三维关系；
- 从确定参数扩展到随机或区间参数；
- 从单目标扩展到多目标权衡；
- 从均匀假设扩展到分区、分时或分群；
- 从连续近似扩展到离散约束；
- 从静态模型扩展到动态状态转移。

每次改进都应说明基础模型遗漏了什么，以及新增结构解决了什么，而不是只写“为了提高精度，引入某算法”。

### 6. 子问题之间复用已经建立的结构

优秀论文会把前一问得到的函数、参数、分类结果或状态关系作为后一问输入，并明确哪些条件发生了变化。这样全文形成同一模型体系的递进，而不是每问重新换一套互不相干的算法。

### 7. 建模时同步设计验证

验证不是论文最后临时补的一节。构建模型时就应回答：

- 哪些约束可以回代检查；
- 哪些参数需要灵敏度分析；
- 是否有极端情形、解析特例或小规模精确解；
- 数据模型怎样划分训练、验证和测试数据；
- 优化算法怎样证明可行、稳定或接近最优；
- 机理模型怎样做量纲、守恒或边界检查。

如果模型无法提出可执行的验证方式，说明模型定义仍不完整。

### 8. 用结果反查模型假设

当结果出现违背常识、约束冲突、边界振荡或过度拟合时，优秀建模不会只调算法参数，而会返回检查变量定义、数据口径、假设和约束。模型构建是“提出—求解—反查—修正”的闭环。

## 四、不同题型的模型构建重点

| 题型 | 构建起点 | 关键闭合环节 | 必要验证 |
|---|---|---|---|
| 物理/机理 | 几何、守恒、运动或传递机制 | 边界条件、初始条件、材料/环境参数 | 量纲、极限情形、实验或数值对照 |
| 优化/调度 | 决策变量和实际规则 | 目标函数、逻辑约束、时间/容量约束 | 可行性回代、最优性界、小规模精确解 |
| 预测/统计 | 数据生成过程和预测目标 | 特征、响应、损失函数、时间划分 | 留出检验、滚动回测、残差和不确定性 |
| 分类/聚类 | 样本含义和相似性 | 距离/标签定义、特征尺度、类别解释 | 稳定性、外部指标、业务可解释性 |
| 综合评价 | “好”的可操作定义 | 指标方向、权重来源、综合规则 | 权重扰动、排序稳定性、替代方法对照 |

## 五、现有 Skill 已经做得较好的部分

现有 `math-modeling` skill 已经包含：

- 先明确输出类型，再选择模型；
- 模型必须覆盖目标、约束、数据特征和评价口径；
- 每问限制独立模型体系数量，避免算法堆叠；
- 区分模型与算法，强调可实现和可验证；
- 要求参数、阈值、假设可追溯；
- 允许基础模型与扩展模型构成同一模型族；
- 编程结果反向修正建模分析。

这些原则方向正确。

## 六、建议补充到 Skill 的内容

### 1. 增加“数学化翻译表”

要求建模手对每个子问题显式列出：题目对象、数学对象、变量、关系、规则、目标、输出、验证。当前 skill 有目标和约束清单，但缺少逐项映射，容易直接跳到模型名称。

### 2. 增加“模型构建链”硬检查

每个主模型必须完整说明：

> 现实对象 → 数学抽象 → 基础关系 → 假设/闭合条件 → 完整数学模型 → 求解算法 → 验证方式

缺少其中任一项时，不进入编程阶段。

### 3. 保留“常见模式”优先级并增加适用性复核

`常见模式.md` 保持现有内容和第一优先级，不改成其他索引。按题型匹配到模式后，再补充回答以下问题，以便把优先模型具体落实到当前题目：

- 数据或机理为什么满足该模型前提；
- 题目中的哪一项结构由该模型表达；
- 与简单基线相比预期解决什么不足；
- 模型失败时怎样识别和回退。

只要优先模式满足题目硬约束、数据前提和可实现性要求，就继续采用；补充检查不用于重新排序原有模式。

### 4. 增加“基础模型—缺陷—改进模型”表达

若使用改进模型，必须先指出基础模型遗漏的具体结构，再说明改进项改变了哪个变量、方程、约束或损失函数，并通过消融或对比验证其价值。

### 5. 增加跨子问题依赖图

要求说明各问之间复用的数据、参数、函数、状态和约束。后一问若更换模型，必须解释是因为目标、机制还是状态变量发生了变化。

### 6. 把验证前置到模型设计

`题目分析报告.md` 中每个模型除“验证方式”外，还应包含：可证伪条件、基线、极端情形、失败信号和回退方案。这样可以避免代码完成后才补灵敏度分析。

### 7. 扩充论文手的语言规范

建议增加一份按句子功能组织的精简参考，包含：定义句、依据句、推导句、求解句、结果句、解释句和限制句。不要堆大量固定句式，只规定每类句子必须包含的信息。

### 8. 增加语言证据检查

交付前自动或人工检查：

- “显著、稳定、合理、有效、较优”是否紧跟证据；
- “可知、说明、表明”之前是否有明确推导或结果；
- 每个公式前后是否说明对象、来源和作用；
- 是否连续罗列算法名而没有题目映射；
- 是否反复使用“我们认为、容易看出、显然”；
- 每个结果段是否同时包含结果和解释；
- 每个关键结论能否定位到计算输出或数学推导。

### 9. 增加反 AI 套话约束

明确禁止：空泛背景、夸大创新、机械排比、同义反复、无证据的“具有较强现实意义”、每节结尾重复“为后续研究奠定基础”。语言应优先保留模型动作、条件、结果和解释。

## 七、可以直接写入 Skill 的核心规则

> 不从算法名称开始建模。先确定输出，完成题目对象到数学对象的映射，再由基础关系、题目规则和必要假设构成闭合模型，最后选择求解算法。

> 每个模型必须形成“现实对象—数学抽象—方程或规则—求解—验证”的完整证据链。改进模型必须指出基础模型的具体缺陷，并验证新增结构确实改善结果。

> 写作时让每句话承担一种明确功能。模型选择给依据，公式给来源和含义，结果给数值或明确判定，评价给证据和适用条件；禁止用算法名和形容词替代论证。

## 八、结合“写作”文件夹后需要增加的内容

### 1. 增加代码—模型—论文三向追踪

论文撰写讲义提出了“把代码逻辑转换成论文语言”，但现有 skill 还可以进一步要求建立三向对应：

| 代码动作 | 数学含义 | 论文表达 |
|---|---|---|
| 读取字段、筛选样本 | 确定研究总体和数据口径 | 数据来源、样本范围与筛选规则 |
| 构造变量 | 定义状态、特征或决策变量 | 变量定义及其实际含义 |
| 损失函数或目标函数 | 确定优化准则 | 目标函数及选择依据 |
| 条件判断和边界处理 | 实现约束或分情形规则 | 约束条件、边界条件和适用范围 |
| 模型训练或求解器调用 | 参数估计或数值求解 | 算法、参数和停止条件 |
| 指标计算 | 模型检验 | 指标定义、数值结果和解释 |

建议在复现清单之外增加内部映射：关键公式对应哪个函数或代码段，正文结果对应哪个输出文件。这样论文手不会只根据代码表面结构猜测模型。

### 2. 增加算法说明的“输入—输出—步骤—停止条件”契约

讲义中的“输入—输出—步骤”结构值得吸收，但还应补充停止条件和参数依据。完整算法说明应包含：

1. 输入数据、维度、单位和预处理状态；
2. 输出对象及其与题目答案的关系；
3. 初始化方式和随机种子；
4. 关键迭代或计算步骤；
5. 超参数、阈值及其来源；
6. 停止条件、可行性处理和失败处理；
7. 计算复杂度或实际运行代价（确有意义时）。

### 3. 增加误差定位与误差归因

讲义不仅要求报告总体误差，还要求指出误差较大的样本或区间。建议把误差分析细化为：

> 总体误差 → 分组/分时段误差 → 最大误差位置 → 误差来源 → 对结论的影响 → 改进方式

误差来源至少区分为数据误差、模型结构误差、参数估计误差和数值求解误差。不能把所有异常都笼统归因于“外部环境变化”。

### 4. 增加多模型选择的多维准则

讲义明确指出不能只根据单一指标选择模型。建议 skill 要求根据任务选择以下维度中的相关项：

- 精度或目标函数值；
- 约束满足程度；
- 稳定性和不确定性；
- 可解释性；
- 计算时间与资源；
- 对样本规模和数据质量的要求；
- 实际部署或决策可操作性。

最终选择必须说明权衡，不能因某一个误差指标最小就宣称模型全面最优。

### 5. 增加假设的“作用—风险—检验”说明

写作材料强调每条假设应服务于模型。建议进一步规定每条关键假设写明：

1. 它关闭了哪个未知关系或排除了哪个因素；
2. 为什么在当前范围内可以接受；
3. 假设失效时哪个结论会受影响；
4. 是否能通过数据、文献、敏感性或情景分析检查。

不能在模型完成后为了凑数量反向生成假设。

### 6. 区分摘要、结果分析和结论的语言任务

- 摘要：压缩“问题—方法—关键结果—验证”，用于快速判断全文完成度；
- 结果分析：解释某一组结果呈现的现象、原因和对当前子问题的回答；
- 结论：综合各问结果，指出总体发现、适用范围和决策含义，不重新介绍详细算法。

现有 skill 对摘要要求较细，但可以增加结论与摘要去重检查。

### 7. 增加 AI 写作的“事实包”输入协议

讲义的 Prompt 库方向正确，但直接让 AI 根据题目“生成模型假设、模型描述或摘要”仍可能补造事实。建议每次写作前提供最小事实包：

- 当前子问题原文和输出要求；
- 已确认的模型名称及选择理由；
- 真实公式、变量和参数；
- 代码入口与运行参数；
- 真实结果表、图或输出文件；
- 允许写入的结论；
- 尚未确认、必须保留为空的问题。

AI 只能重组事实包中的内容；缺失项应标记为待补充，不得自行完成。

## 九、“写作”文件中不应直接吸收进 Skill 的内容


### 3. 不把更换算法等同于稳健性检验

更换求解算法后结果接近，只能说明数值求解对算法选择可能不敏感；它不能单独证明模型面对数据扰动、参数变化或分布偏移仍然稳健。

### 4. 删除无证据的绝对评价

“精度优异、抗干扰能力强、普适性极强、证明结论无偶然性”等措辞只有在明确基准、统计检验和适用范围支撑时才能使用。否则应改为报告具体指标和有限结论。

### 5. 不接受“单位根据题目数据确定”作为终稿内容

无法确认单位时应返回数据字典、题目或领域定义核实。单位确实不存在时写“无量纲”，不能用模糊占位语掩盖未完成工作。

### 6. 不机械追求希腊字母

符号选择应服从领域惯例、语义清晰和全文一致。英文字母、希腊字母都可以使用；避免中文变量主要是为了公式兼容性，而不是因为希腊字母更专业。

### 7. 以原有常见模式为首选，再完成落地检查

讲义中的题型表用于辅助识别题型；具体方法仍以 skill 的 `常见模式.md` 为第一优先级。选中模式后，再检查数据前提、题目结构、基线方法和失败条件，使该模式能够正确落地。

## 十、建模方法选取需要补充的规则

本节只补充原 `常见模式.md` 的执行细节，不改变其中的模型顺序、组合方式和优先级。执行顺序为：**先按常见模式确定首选方案并实际建模、实现和验证 → 成功则保留原方案 → 只有取得可复核的失败证据后才允许改变。** 不能因“可能不合适”、个人偏好或存在更新算法而跳过原优先模式。

### 0. 原模式失败后才允许切换（硬门禁）

只有出现以下至少一类证据，才认定原优先模式行不通：

1. 题目硬约束无法写入或求得的方案持续不可行；
2. 模型必要前提经数据检验明确不成立，且无法通过同模型族内的合理扩展修复；
3. 参数或状态不可识别，现有数据无法支持估计；
4. 按合理参数、尺度变换和数值设置实现后仍不收敛、超出竞赛计算资源或无法复现；
5. 在正确验证方案下，结果持续劣于原 skill 要求的基线或无法回答题目；
6. 编程阶段发现公式、约束或数据接口存在不可消除的冲突。

切换顺序固定为：

> 原模式参数修正 → 原模型族的简化/扩展版本 → 原模式中的备选方案 → 其他模型。

每次切换必须记录原方法、实际运行或检验、失败证据、已尝试的修正和选择新方法的理由。没有实际失败记录，不改变原方法。

### 1. 区分候选模型池与最终模型体系

“每个子问题最多两个模型体系”应约束最终论文，而不限制前期了解备选方法。候选池首先放入 `常见模式.md` 给出的优先模型和组合；其他候选主要作为比较、校验或失败回退。最终仍保留原模式中的主模型，或主模型加一个具有明确比较、校验或串联价值的模型。

### 2. 按常见模式确定首选方案后做六维核对

每个子问题先回答：

1. 输出是解释、预测、分类、排序、最优方案还是控制策略；
2. 主要信息来自机理、规则、数据还是专家判断；
3. 系统是静态还是动态、确定还是随机、连续还是离散；
4. 约束、时间顺序、空间关系和网络关系是否构成核心结构；
5. 数据规模、维度、标签、缺失和噪声是否支持候选模型；
6. 结果更重视精度、解释、稳定、速度还是可执行性。

核对结果用于确认首选模式怎样落地。只要没有出现数据、约束、可识别性或实现条件上的硬冲突，就保持 `常见模式.md` 的原首选方案。

### 3. 增加机理模型、数据模型和混合模型的选择门槛

以下内容用于细化优先模式内部的具体建模形式，不改变模式优先级：

- 有明确物理、几何、守恒或业务规则时，优先建立机理或规则模型；
- 机理不完整但数据充分时，采用统计或机器学习模型，并限制结论为数据覆盖范围内的经验关系；
- 机理能够确定骨架、数据能够估计未知参数或修正残差时，采用混合模型；
- 数据少且机理也弱时，不应直接使用高复杂度模型，应报告可识别范围和不确定性。

### 4. 增加可识别性与可估计性检查

在选择模型前检查：现有观测是否足以区分模型参数或状态；参数数量是否与样本量相称；多个参数是否产生近似相同的输出；关键变量是否根本没有观测代理。不可识别的模型即使能够拟合，也不能可靠解释或外推。

### 5. 强制建立简单基线

复杂模型必须与一个可解释、可复现的简单基线比较，例如朴素预测、线性模型、规则方案、精确小规模模型或题目给定方案。只有当复杂模型在预先指定的指标上稳定改进，并且新增复杂度有实际价值时，才保留复杂模型。

### 6. 按常见模式选择优化算法并补充求解核对

继续执行原模式：小规模问题优先精确规划，大规模 NP-hard 问题优先启发式算法。在此基础上补充：

1. 精确规划说明变量类型、可行域和求解器状态；
2. 大规模问题使用遗传算法、粒子群或模拟退火时，说明规模和复杂性依据；
3. 可用分解、剪枝、松弛或降维提升优先算法的效率；
4. 启发式结果使用小规模精确解、上下界、基准方案或多次运行稳定性进行校验；
5. 只有原优先算法因硬约束、数据条件或实现条件无法使用时才切换回退方法。

### 7. 按不确定性来源选择方法

- 已知或可估计概率分布：概率模型、随机规划或蒙特卡洛；
- 只有参数区间：区间分析或鲁棒优化；
- 只有若干可能情景：情景分析；
- 分布本身可能变化：分布鲁棒方法或压力测试；
- 不确定性很弱且不会改变决策：确定性模型加敏感性分析即可。

不能把所有不确定问题都统一处理成蒙特卡洛模拟。

### 8. 让验证条件参与选模

优先选择能够被当前数据和题目条件验证的模型。若某候选模型需要长期外部数据、真实标签或实验条件，而题目无法提供，就必须降低其优先级或明确验证缺口。不能先选模型，再临时寻找一个无关指标证明它有效。

### 9. 增加时间与空间数据的泄漏门禁

时间序列不能随机打乱后划分训练测试集；空间数据需要避免相邻样本同时进入训练和测试造成空间泄漏；同一对象的重复观测也不能跨集合泄漏。候选模型若无法在正确划分下验证，其高精度结果无效。

### 10. 增加模型选择评分表，但不机械加权

对通过基本前提检查的候选模型，至少比较：

| 维度 | 核心问题 |
|---|---|
| 结构匹配 | 是否表达题目最关键的机制、规则和约束 |
| 数据前提 | 样本、标签、分布和时间空间结构是否满足要求 |
| 可识别性 | 参数和状态能否由现有数据确定 |
| 可验证性 | 是否有真实可执行的检验方案 |
| 可实现性 | 能否在竞赛时间和计算资源内稳定求解 |
| 可解释性 | 能否说明变量、约束和结果的实际含义 |
| 稳定性 | 对采样、参数和初值变化是否敏感 |
| 复杂度收益 | 相比简单基线是否有稳定、必要的改进 |

评分表用于暴露权衡，不建议机械加权得到一个“总分最高模型”。最终选择应由题目目标和硬约束决定。

### 11. 记录淘汰理由和回退条件

每个被淘汰候选至少记录一个具体原因，例如不满足平稳性、样本不足、参数不可识别、计算时间超限、无法处理硬约束或正确验证后性能不稳定。主模型还要记录失败信号及回退模型，便于编程阶段出现问题时快速调整。

### 12. 执行原常见模式时的补充核对

- 按原模式优先采用 AHP 时，补充说明专家判断或成对比较信息的来源；
- 按原模式优先采用灰色预测时，补充检验序列形态、级比和预测范围；
- 按原模式采用双模型对比或集成时，补充检查模型误差互补性及独立验证结果；
- 按原模式对大规模问题采用启发式算法时，补充规模依据、收敛性和小规模对照；
- 按原模式使用 TOPSIS 选择多目标折衷解时，补充权重、归一化和排序稳定性检查。
