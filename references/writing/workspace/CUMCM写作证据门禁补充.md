# CUMCM 写作证据门禁补充

## 1. 文档定位

本文件是 `cumcm-step-review` 的窄范围补充，只负责检查论文语言是否由模型、代码和结果充分支撑，不替代原 skill 中已有的章节结构、摘要模板、图表规范、排版要求和分步审核流程。

执行优先级如下：

1. 赛题与当届官方规范；
2. `cumcm-step-review` 主流程及其写作规范；
3. 本文件的语言与证据门禁。

若本文件与前两项冲突，以前两项为准。

## 2. 适用时机

在撰写或修改下列内容前后调用本门禁：

- 模型建立、模型求解与算法描述；
- 结果分析、误差分析、灵敏度分析和稳健性分析；
- 模型评价、模型推广、摘要与结论；
- 多模型比较及模型切换说明；
- 将程序输出写入论文正文、表格或图形时。

本门禁不改变已经确认的建模方案。模型是否更换仍按原 CUMCM 工作流处理：优先实际运行、修正和验证原方案，只有出现可复核的失败证据时才进入模型切换。

## 3. 写作前事实包

论文手开始写作前，应取得下列最小事实包。缺失项必须标为“待确认”，不得自行补造。

| 信息项 | 最低要求 |
|---|---|
| 问题目标 | 明确本问要预测、评价、优化、分类还是解释什么 |
| 模型名称 | 与实际采用的模型、变体和求解算法一致 |
| 核心关系 | 给出目标函数、约束、状态转移或统计关系 |
| 参数与单位 | 参数含义、来源、取值及量纲可追溯 |
| 数据处理 | 缺失值、异常值、标准化和样本划分方法明确 |
| 代码入口 | 对应脚本、函数或可复现实验入口明确 |
| 结果来源 | 正文数字能对应到输出文件、表格或图形 |
| 检验结果 | 至少包含与任务相匹配的有效性检验 |
| 可下结论 | 明确证据能够支持到什么程度 |
| 未知事项 | 尚未计算或不能确认的内容显式列出 |

## 4. 核心写作门禁

### 4.1 段落功能门禁

每个技术段落应承担一个清晰的主要功能，避免在同一段中无序混合定义、推导、结果和评价。常见功能包括：

- 定义对象或指标；
- 说明选取理由；
- 建立数学关系；
- 描述求解过程；
- 报告结果；
- 解释结果；
- 指出适用条件或局限。

相邻段落宜形成“为什么建模—怎样建模—怎样求解—得到什么—结果说明什么”的推进关系。

### 4.2 公式叙述闭环

重要公式不能只出现编号和符号。公式附近应尽量交代：

1. 公式用于解决什么问题；
2. 关系来自题意、定义、文献还是推导；
3. 成立依赖哪些假设；
4. 主要符号与单位是什么；
5. 该式在后续计算或决策中承担什么作用。

对于常规变形可适当压缩，但关键目标函数、约束条件、评价指标和状态方程必须形成叙述闭环。

### 4.3 模型构建叙事链

模型建立部分优先采用以下逻辑链，而不是堆叠算法名称：

> 现实机制或任务目标 → 必要抽象 → 变量关系 → 约束或闭合条件 → 求解方法 → 有效性验证

如果使用多个模型，应说明它们分别解决哪个子问题以及前后如何传递数据，不能只用“首先、其次、最后”进行表面串联。

### 4.4 结果分析五要素

重要结果段落至少覆盖下列五类信息中的前四类，关键结论应尽量全部覆盖：

1. **证据**：给出数值、区间、排序、图表或检验统计量；
2. **现象**：说明变化方向、拐点、聚类、差异或异常；
3. **幅度**：说明变化有多大，而非只写“明显提高”；
4. **参照**：与基线、原方案、其他模型、历史值或阈值比较；
5. **解释与回应**：结合机制解释，并明确回答赛题问题。

推荐句式：

> 由表（图）可见，在……条件下，指标由……变化至……，相较基线变化……%。这一现象主要与……有关，说明……，因此对问题……可得到……结论。

句式仅提供信息顺序，不要求机械照抄。

### 4.5 误差定位与归因

误差分析不能停留在“模型存在一定误差”。应尽量回答：

- 误差发生在哪些样本、时间段、区域或参数区间；
- 偏差是系统性还是随机性，方向是高估还是低估；
- 误差可能来自数据、模型假设、参数估计、数值求解还是外生扰动；
- 归因是否有残差图、分组统计、消融实验或敏感性结果支持；
- 误差是否会改变核心结论。

若没有证据，应使用“可能与……有关”“尚不能排除……”等有限表述，不得把推测写成确定事实。

### 4.6 多模型比较语言

比较模型时不得只写“模型 A 优于模型 B”。至少明确比较维度，例如：

- 预测或拟合精度；
- 稳定性与敏感性；
- 可解释性；
- 数据需求；
- 计算复杂度；
- 对假设的依赖；
- 对本题目标和约束的适配程度。

模型切换说明必须引用实际失败证据。应区分：

- 模型结构失配；
- 参数设定不当；
- 求解器未收敛；
- 代码实现错误；
- 数据质量不足。

后三类问题不能直接证明模型本身失败。

### 4.7 代码—模型—论文可追溯性

关键结论应能沿以下链条回溯：

> 论文结论 → 图表或数值 → 输出文件 → 代码函数或脚本 → 数学公式与参数 → 原始或处理后数据

建议在内部审核记录中维护下表，是否放入最终论文可按篇幅决定：

| 论文位置 | 结论或数字 | 图表/输出来源 | 代码入口 | 对应模型 | 核验状态 |
|---|---|---|---|---|---|
| 示例：5.2 节 | 待填写 | 待填写 | 待填写 | 待填写 | 待核验 |

### 4.8 强判断词证据检查

出现下列词语时，必须检查是否存在直接证据：

- 显著、明显、充分证明；
- 最优、完全、准确、必然；
- 稳健、鲁棒、普适；
- 大幅提高、有效避免、彻底解决；
- 与实际完全一致。

如果没有统计检验、对照实验、理论证明或充分结果支撑，应改为更准确的有限表达，例如“在当前样本与参数范围内表现较好”。

### 4.9 语言自然度检查

优秀论文的语言通常克制、具体、连续。终稿应删除或改写：

- 与内容无关的套话和空泛背景；
- 连续使用“首先、其次、再次、最后”的机械段落；
- “为了更好地……”等没有实际信息的过渡句；
- 反复复述题目而不增加数学含义的句子；
- 只罗列模型名称、软件名称或指标名称的段落；
- 无数据支撑的赞美式模型评价；
- 为追求复杂感而增加的无效术语、符号和希腊字母。

优先使用“对象 + 操作 + 条件 + 结果 + 含义”的具体句式，并保持术语、变量名、单位和时态一致。

## 5. 摘要与结论的差异化要求

摘要应压缩呈现“问题—方法—关键结果—结论”，关键结果尽量包含有辨识度的数值。结论部分则应按问题逐项回答，并补充适用条件、局限和可执行含义。

不得把正文段落简单复制到摘要，也不得把摘要原样扩写成结论。摘要强调全篇信息密度，结论强调问题回应和结果边界。

## 6. 停止写作并退回的条件

出现以下任一情况时，论文手应停止生成确定性文字，并将问题退回对应环节：

- 正文数字与程序输出不一致；
- 公式、变量、代码实现之间无法对应；
- 参数来源、单位或数据口径不明；
- 声称完成了实际并未执行的检验；
- 将求解器、代码或数据问题误写为模型失败；
- 模型更换缺少原方案实际运行及失败记录；
- 结果不足以支撑“最优、显著、稳健”等结论；
- 关键事实只能依靠猜测补全。

退回时应明确指出缺失信息、影响的论文位置和所需补充材料，避免只写“数据不足”或“需要完善”。

## 7. 终稿核验清单

- [ ] 每个问题均形成“任务—模型—求解—结果—回答”的闭环。
- [ ] 每个重要公式均说明用途，主要符号和单位一致。
- [ ] 关键数字均能追溯到真实程序输出。
- [ ] 图、表、正文中的同一指标数值一致。
- [ ] 结果分析包含证据、幅度、参照和问题回应。
- [ ] 误差分析定位到具体对象，并区分事实与推测。
- [ ] 多模型比较说明了维度，模型切换具有实际失败证据。
- [ ] “显著、最优、稳健”等词均有匹配证据。
- [ ] 摘要与结论功能不同，没有机械复制正文。
- [ ] 未编造数据、参数、检验、文献、代码行为或模型表现。
- [ ] 删除了空泛套话、无效术语和机械连接词。
- [ ] 所有未知事项均已确认，或以边界清楚的方式披露。

## 8. 与原 CUMCM skill 的关系

本文件只增加写作阶段的“证据门禁”和“语言自检”。原 skill 已有的章节模板、优秀论文写法、摘要规范、图表规范、自审框架和用户审核节点继续优先使用，不在此重复建设。

建议将本文件作为论文手生成正文前的输入检查表，以及每一问写完后的二次核验表；发现问题时回到原工作流的建模手、编程手或论文手对应节点修正。
