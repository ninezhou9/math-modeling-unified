# 质量门禁与验收规范

当终审需要核对优秀论文质量特征的来源归纳时，按需读取[优秀论文特点与补充建议](../writing/workspace/优秀论文特点与Skill补充建议.md)，不得用其替代本页的可执行验收门禁。

本文件规定数学建模全流程各阶段自检、用户审核及最终交付的硬性验收门禁。

```yaml
author_self_check: true
user_review_hard_gate: true
final_acceptance_checks:
  - reproduction_manifest
  - paper_check_script
  - visual_pdf_check
  - formula_native_check
```

## 质量门禁三层防护体系

### 第一层：阶段自检（author_self_check）
每个角色在完成对应阶段的工作后，必须依据清单进行作者自检：
1. **建模手自检**：子问题分解是否完全无遗漏；模型数量是否合规（$\le 2$ 个独立体系）；是否有可执行的模型数学表达与输入输出定义；基线模型与对比方案是否明确。
2. **编程手自检**：代码是否真实运行成功且退出码为 0；是否生成了可复现的中间与最终数据表；是否导出了符合分辨率且无图内标题的图表；是否完整生成了 `results/复现清单.json`。
3. **论文手自检**：正文段落功能是否完备；图表前后是否有引导与分析；公式符号是否有物理单位；强判断词是否有具体统计数据支撑。

### 第二层：用户审核硬门禁（user_review_hard_gate）
- 用户审核是推进阶段的**绝对硬性门禁**。
- 每个子问题或章节完成后，必须写入 `论文草稿.docx` 并呈递用户审核。
- 只有用户明确审核通过后，该部分才正式标记为"冻结"；用户提出修改意见时，必须修改并重新提交审核，未获批准禁止推进下一部分。

### 第三层：终稿核验与最终验收（final_acceptance_checks）
在全篇正文和摘要均冻结后，必须执行以下 4 项终稿核验：

1. **复现清单核验（reproduction_manifest）**：
   检查 `results/复现清单.json`，确保所有图表、表格与关键数值均可由代码一键重新计算生成，环境依赖与随机数种子记录完备。
2. **自动化脚本检查（paper_check_script）**：
   运行自动化核验脚本（如 `paper_check.py`），检查字数分布、图表引用完整性、双向文献引用与排版一致性。
3. **PDF 视觉检查（visual_pdf_check）**：
   对 LaTeX/Word 编译生成的最终 PDF 进行全文视觉排版巡检，检查是否有公式溢出页面边界、孤行断页、跨页断表或图文重叠。
4. **原生公式与表格检查（formula_native_check）**：
   核验 Word 文档中的数学公式是否为原生 OMML/MathML 格式（严禁公式截图插图），表格是否为标准三线表。

## 硬错误阻断原则

任何一项最终核验不通过或发现硬错误（如代码无法运行、数值前后矛盾、图表缺失、公式截图），一律判定为未完成，立即阻断交付并回退修复。
